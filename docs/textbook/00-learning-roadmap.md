# 第 00 章　学习路线图

> 本章目标：知道自己要学什么、按什么顺序学、学完之后应该能做到什么。

---

## 0.1 这本教材要解决的问题

你已经有一个能运行的项目——MagicStream Movies（前端品牌名叫 **Reelm**）。但“能运行”和“我能独立写出来”是两回事。这本教材的最终目标是：

1. **理解**：能说清楚每个文件、每个函数为什么存在。
2. **解释**：能把这个项目讲给另一位开发者听，并回答他的追问。
3. **重建**：合上教材，从一个空文件夹开始，不借助 AI，重新写出功能相同的应用。
4. **批判**：能指出现有实现的缺陷（本项目确实有几个真实的 bug 和安全问题），并知道如何修复。

第 4 点很重要。职业软件工程师不仅要会写代码，更要会**审视**代码。所以本教材不会把现有代码当作“标准答案”来膜拜，而是会诚实地指出问题。

## 0.4 推荐学习顺序（四个阶段）

### 阶段 A：建立全局认识（约 1 天）
- 第 01 章：项目做什么。
- 第 02 章：各部分如何连接。
- **检验标准**：能在白纸上画出前端、后端、数据库、OpenAI 之间的箭头，并标出每条箭头传输的是什么数据。

### 阶段 B：后端基础（约 5–7 天）
- 第 03–06 章：环境、初始化、目录、依赖。
- 第 07–09 章：数据库、Model、路由和 Controller。
- **检验标准**：不看代码，写出 `GET /movies` 这个接口，并用 `curl` 拿到数据。

### 阶段 C：认证与横切关注点（约 5–7 天）
- 第 10 章：业务逻辑（推荐、AI 评级）。
- 第 11 章：认证（本项目最复杂、最值得学的部分）。
- 第 12–13 章：Middleware、校验、错误处理。
- **检验标准**：能画出 Access Token 过期后、前端自动刷新并重试请求的完整时序图。

### 阶段 D：前端、整合与工程化（约 5–7 天）
- 第 13a 章：React 前端。
- 第 14 章：端到端追踪一个请求。
- 第 15–17 章：测试、安全、部署。
- 第 18 章：从零重建。
- 第 19–21 章：练习、答案、改进路线。
- **检验标准**：在一个新目录中重建整个项目，并修复第 21 章列出的至少 5 个问题。

## 0.5 学习方法建议

1. **手敲，不要复制粘贴。** 重建时每一行都自己敲。肌肉记忆和“卡住时的思考”才是真正的学习。
2. **先预测，再运行。** 每次运行代码前，先在纸上写下你预期的输出。结果不同时，正是理解加深的时候。
3. **故意破坏。** 删掉一行 `return`、改错一个 struct tag，观察会发生什么。本教材的「调试挑战」就是这么设计的。
4. **用自己的话复述。** 每章结束后，用三句话总结本章内容，写在笔记里。
5. **练习先做后看。** 答案在第 20 章，做完再对照。

## 0.6 术语表（首次出现时会再解释）

| 术语 | 简单解释 |
|---|---|
| Handler | 处理某个 HTTP 请求的函数 |
| Middleware | 在 Handler 之前/之后执行的“拦截器”函数 |
| Context（Go） | 携带截止时间、取消信号和请求范围数据的对象 |
| `gin.Context` | Gin 框架封装的“本次请求的一切”：请求、响应、参数、键值存储 |
| JWT | JSON Web Token，一种带签名的、自包含的令牌格式 |
| Access Token | 短期令牌，用于访问受保护的 API |
| Refresh Token | 长期令牌，只用于换取新的 Access Token |
| Pointer（指针） | 保存另一个变量内存地址的变量，Go 中写作 `*T` |
| Interface（接口） | 一组方法签名；任何实现了这些方法的类型都“满足”该接口 |
| Closure（闭包） | 引用了外部变量的函数 |
| Dependency Injection（依赖注入） | 把函数需要的依赖（如数据库连接）从外部传进去，而不是在内部创建 |
| CORS | 跨源资源共享，浏览器限制跨域请求的安全机制 |
| BSON | MongoDB 使用的二进制 JSON 格式 |
| Hook（React） | 以 `use` 开头的函数，让函数组件拥有状态和副作用 |
